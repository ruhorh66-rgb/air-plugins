## Сборка сайта из брифа
**Статус: AVAILABLE**

Читает `brief.yaml` + контент-документы и производит собранный Next.js
(App Router + TypeScript + Tailwind + shadcn/ui + Framer Motion) сайт с
`SITE_REPORT.md`. Один прогон = один сайт, не пайплайн.

- **Контракт:** вход — папка брифа; выход — Next.js-проект + `SITE_REPORT.md`.
- **Проверка:** `npm run build` (Phase 4) обязателен перед сдачей; дополнительно
  запускаются `scripts/gates.mjs`.
- **Ограничения:** не серийная генерация; требует Node.js на PATH; не
  публикует и не деплоит без явного решения пользователя.

## Дизайн-система и токены
**Статус: AVAILABLE**

Подбирает направление и палитру/типографику/spacing из вендорных баз
(`design-taste-frontend`, `design-system`, `ui-ux-pro-max`) и проверяет
вёрстку на соответствие токенам.

- **Проверка:** `python skills/design-system/scripts/html-token-validator.py
  <файл.html>` — код возврата по хардкод-значениям (hex/rgb/rgba/hsl/шрифт
  мимо `var()`); это же — канонический гейт цикла `build-site`.
- **Ограничения:** вендорные базы read-only с точки зрения продукта.

## Генерация визуалов через Glif
**Статус: EXPERIMENTAL**

Опциональный шаг Phase 3b: подбирает Glif-воркфлоу и генерирует
hero/иллюстрации/иконки/OG-изображения.

- **Почему не AVAILABLE:** ни один скрипт репозитория не проверяет, что
  сгенерированные файлы существуют, сохранены локально и соответствуют
  дизайн-системе — успех виден только в ответе одного MCP-вызова.
- **Ограничения:** нужен опциональный `glif_api_token`; без него — штатный
  fallback на явные заглушки без блокировки сборки; бренд-критичные визуалы
  не генерируются никогда (policy, не механизм).

## Аудит анимаций (`improve-animations`)
**Статус: EXPERIMENTAL**

Read-only аудит движения по восьми категориям → приоритизированный `AUDIT.md`
+ самодостаточные планы. Ничего не применяет сама.

- **Почему не AVAILABLE:** оценка идёт по текстовому каталогу правил силами
  модели; ни один скрипт не проверяет находки механически.

## Проверка диффа анимаций (`review-animations`)
**Статус: EXPERIMENTAL**

Ревью motion-кода диффа против `STANDARDS.md`: таблица находок + вердикт
Approve/Block.

- **Почему не AVAILABLE:** вердикт — суждение модели, ничем не проверяется.
- **Дополнительное ограничение:** апстрим ставит `disable-model-invocation:
  true` — оркестрирующий агент/скилл вызвать её сам не может, только
  пользователь командой `/review-animations`.

## Выпуск SSL-сертификата (`issue-ssl-cert`)
**Статус: AVAILABLE**

Самостоятельная утилита вне пайплайна брифа: выпускает мультидоменный Let's
Encrypt сертификат через минимальный ACME v2 (HTTP-01) клиент без CLI и без
регистрации аккаунта.

- **Проверка:** явно названный внешний gate — `openssl s_client -connect
  host:443 -servername host -verify_hostname host` (или `curl` без `-k`) с
  машины, не участвовавшей в выпуске.
- **Ограничения:** требует `openssl` на PATH и FTP-доступ на запись в докрут;
  финальная загрузка сертификата в панель хостинга — ручной шаг.

## Гейты качества сайта (`scripts/gates.mjs`)
**Статус: AVAILABLE**

Единая точка запуска: доступность (axe, pa11y), Core Web Vitals
(Lighthouse/Unlighthouse), битые ссылки (lychee), schema.org (sdtt), sitemap
(xmllint), клавиатурный фокус (Playwright). Ни один шаг не обращается к LLM.

- **Проверка:** скрипт сам себе гейт — код возврата, явные правила
  (пропавший инструмент → `not_run` с причиной, нечитаемый вывод → `fail`,
  никогда молчаливый `pass`). Живой прогон 08.09.2026 на SRVLM01: 1 pass,
  3 fail, 3 not_run, код возврата 1 — реальные находки, не заглушка.
- **Ограничения (среда, не дефект пути):** на SRVLM01 на дату записи не
  установлены `lychee`, `xmllint`/libxml2, Chromedriver, Playwright+Chromium
  — соответствующие секции дают `not_run` с командой установки. Полностью
  зелёного прогона на этой машине быть не может, пока они не поставлены.

## Клавиатурный проход и видимость фокуса (`scripts/keyboard-focus.mjs`)
**Статус: AVAILABLE**

Закрывает пробел, который не покрывают axe/pa11y: реальная табуляция по
интерактивным элементам (Playwright) со сравнением фокусного/нефокусного
computed style.

- **Проверка:** самопроверяющийся скрипт — код возврата 1 при fail;
  отсутствие Playwright/Chromium → `not_run` с причиной и командой установки.
- **Ограничения:** не заходит в same-origin iframes/open shadow roots;
  «видимый фокус» приближается через outline/box-shadow — чистая смена
  цвета текста без outline/shadow не обнаруживается; на этой машине
  Playwright не установлен (то же ограничение среды, что у гейтов выше).

## Отдельная проверка sitemap (`scripts/sitemap_check.py`)
**Статус: EXPERIMENTAL — понижено против ожидания**

Самостоятельный Python-скрипт без внешних зависимостей: проверяет
корректность XML и структурные правила протокола sitemaps.org (namespace,
лимиты, обязательный `<loc>`). Тест-прогон в рамках этого аудита подтвердил,
что скрипт исправен (синтетический sitemap → `pass`, код возврата 0).

- **Почему не AVAILABLE, хотя сам скрипт рабочий:** он не вызывается ни из
  `scripts/gates.mjs`, ни из `skills/build-site/SKILL.md`, ни из какого-либо
  `agents/*.md`. Секция `sitemap` в `GATES.json` сегодня формируется другой,
  независимой реализацией внутри `gates.mjs` через системный `xmllint`, а не
  этим скриптом. DEV-050 п.4 требует, чтобы help/docs получали capability из
  того же source-of-truth, что и runtime — сегодня этот скрипт нигде не
  упомянут за пределами собственного файла.
- **Что это значит практически:** дополнительная ценность скрипта (проверка
  правил протокола sitemaps.org, которых `xmllint` не знает) сегодня никому
  не доступна, пока его не подключат к `gates.mjs` или не задокументируют как
  самостоятельный ручной инструмент.

## Делегирование трём ролям (`agents/`)
**Статус: AVAILABLE**

Три специализированные роли с фиксированной моделью и ограниченным набором
инструментов:

| Роль | Модель | Задача |
|---|---|---|
| `site-page-builder` | haiku | одна страница из готовых токенов и контента |
| `site-designer` | sonnet | дизайн-направление, палитра, типографика |
| `site-reviewer` | opus | независимый вердикт PASS/BLOCK перед сдачей |

- **Проверка:** frontmatter каждого файла машинно проверяем — поля `model:`
  и `tools:` присутствуют и заданы явно; это тот же метод приёмки, которым
  собственный план продукта (`docs/GOAL.md`, §5) измеряет эту возможность.
- **Ограничения:**
  - верификация покрывает конфигурацию (наличие полей), не функциональный
    результат ролей — end-to-end регрессии нет;
  - `cacheTtl: 1h`, который `skills/build-site/SKILL.md` и `docs/GOAL.md`
    называют нужным при серийных вызовах одной роли, сегодня **не прописан**
    ни в одном из трёх файлов `agents/*.md`;
  - `agents/site-builder.md` — точка входа всего пайплайна, а не одна из
    трёх делегируемых ролей; относится к capability «Сборка сайта из брифа».

## Известные ограничения среды (не статус)

Часть гейтов (`lychee`, `xmllint`, Chromedriver для axe, Playwright для
клавиатурного фокуса) не установлена на этой машине (SRVLM01) на дату записи.
Это ограничение конкретного окружения, а не понижение статуса capability:
сам runtime-path исполним, и скрипт корректно репортит `not_run` с причиной
и командой установки вместо молчаливого пропуска или ложного `pass`. Список
команд установки — в `docs/SITE_BUILDER_LIVING_DOCUMENT.md`, раздел
«Состояние гейтов на SRVLM01».
