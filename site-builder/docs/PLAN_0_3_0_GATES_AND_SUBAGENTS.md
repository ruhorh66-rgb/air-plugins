# Задача: site-builder 0.3.0 — измеримые гейты и делегирование

Статус: **draft_for_review**. До явного согласования ЛПР работа не начинается.
Дата: 08.09.2026. Основание: стандарт AIR VIBE CODING v2.0.0-rc.6, инварианты 1–11.

---

## 1. Цель

### 1.1 Результат

Сборщик сайтов проверяет своё качество **числами, полученными от скриптов**, а не утверждениями модели, и умеет отдавать подзадачу субагенту с заранее назначенной моделью.

Проверяется одной командой: на собранном сайте прогон гейтов выдаёт отчёт с числами по доступности, скорости, ссылкам и разметке, и этот отчёт получен без участия LLM.

### 1.2 Состояние

Сегодня сборщик проверяет три вещи: сборка проходит, страница рендерится в предпросмотре, валидатор токенов отрабатывает. Всё остальное, что перечислено в его же скилле — доступность, контраст, LCP, CLS, битые ссылки, разметка — **не измеряется ничем**. Это текст, а не гейт.

Делегирования нет: в плагине один агент `site-builder`, который делает всё в одном контексте. Модель под подзадачу не назначается.

Прямое следствие для сайта ЮНИТЕХ: половина гейтов его плана сегодня нечем закрыть.

## 2. Механизм

Три части, в порядке ценности. Первая обязательна, третья может не понадобиться вовсе.

### 2.1 Гейты на скриптах — основа

Правило стандарта: самая дешёвая проверка не модель, а скрипт. Модель нужна там, где требуется суждение; где требуется факт, нужен скрипт. Поэтому сначала гейты, потом всё остальное.

Один входной скрипт `scripts/gates.mjs` запускает проверки и складывает машинный отчёт `GATES.json` плюс человекочитаемый `GATES.md`. Ни один шаг не спрашивает модель.

| Гейт | Инструмент | Лицензия |
|---|---|---|
| доступность WCAG AA | axe-core CLI | MPL-2.0 |
| доступность, второй взгляд | pa11y | LGPL-3.0 |
| LCP / CLS / INP, мобильный профиль | Lighthouse CI | Apache-2.0 |
| обход сайта целиком | Unlighthouse | MIT |
| битые ссылки | lychee | Apache-2.0 / MIT |
| schema.org, в том числе JobPosting | structured-data-testing-tool | ISC |
| sitemap | xmllint | MIT |
| вёрстка мимо токенов | eslint-plugin-tailwindcss, правило `no-arbitrary-value` | MIT |
| токены как источник | Style Dictionary | Apache-2.0 |

Известный пробел, который закрывать нечем: **клавиатурный проход и видимость фокуса**. Готового открытого средства нет — axe и pa11y ловят структуру, но не проверяют, виден ли фокус при табуляции. Здесь пишется свой скрипт на Playwright, и в плане он числится отдельной работой, а не «покрыт axe».

### 2.2 Делегирование — по документированной механике

Субагенты объявляются файлами `agents/*.md` с полями `model`, `tools`, `disallowedTools`, `isolation`. Контекст субагента изолирован: истории родителя он не видит, значит верстка страницы перестаёт раздувать контекст оркестратора.

Роли ставятся по лестнице стандарта:

| Роль | Модель | Почему |
|---|---|---|
| генерация страницы по готовому шаблону и токенам | haiku | однотипный объём, суждения не требует |
| дизайн-направление, бренд, тексты | sonnet | нужно суждение |
| независимая проверка перед сдачей | opus | цена ошибки выше цены токенов |

Два ограничения из документации, которые надо соблюсти: глубина вложенности не более трёх, одновременно не более двадцати; если субагенты пишут в одни файлы — `isolation: worktree`.

Экономия здесь достигается не выбором модели, а **кэшем**: у субагента собственный кэш промпта, по умолчанию он гаснет через пять минут. При генерации страниц одна за другой ставится `cacheTtl: 1h`, иначе каждый вызов греется заново.

### 2.3 Автоматизация — не нужна

Обоснование, а не мнение. Семейство Automation стандарта включается при controller, worker, watchdog, autonomy или reporting. У сборщика нет ни одного: он запускается решением ЛПР, отрабатывает и заканчивается. Постоянной беспризорной работы нет, сторожить нечего.

Инвариант 5 добавляет: рой берётся под существенную разработку, локальную работу оркестратор делает сам, если рой не даёт выигрыша.

Поэтому реестра автоматизации, контроллера и надзора продукт не получает. Если позже появится регулярная беспризорная работа — решение пересматривается, но не раньше.

## 3. Источники

Reuse-check пройден в порядке, который требует инвариант 3.

1. **`E:/-5-/014_Skills`** — единственный близкий кандидат `air-automation-runtime`: примитивы для контроллеров продуктовой автоматизации. Контроллера у нас нет. Вердикт: **брать нечего**.
2. **Локальные репозитории** — сам плагин `E:/-7-/site-builder` 0.2.2, вендорные скиллы дизайна на месте.
3. **Внутренний GitHub** — отдельного решения этой задачи нет.
4. **Внешний upstream** — девять инструментов из таблицы 2.1, лицензии проверены, четыре репозитория сверены вручную.

Документация механики субагентов: `code.claude.com/docs/en/sub-agents.md`, `.../agents.md`, `.../prompt-caching.md`, `.../costs.md`.

Вердикт по цепочке: **ADAPT_EXTEND** — берём готовые инструменты под открытыми лицензиями, свой код пишем только там, где готового нет (клавиатурный проход) и где нужна склейка.

## 4. Результат

Что появляется в плагине:

- `scripts/gates.mjs` — единая точка запуска проверок, выход `GATES.json` и `GATES.md`;
- `scripts/keyboard-focus.mjs` — свой скрипт на Playwright под непокрытый гейт;
- `agents/site-page-builder.md`, `agents/site-designer.md`, `agents/site-reviewer.md` — три роли с назначенными моделями и ограниченным набором инструментов;
- правка `skills/build-site/SKILL.md`: фаза проверки ссылается на `gates.mjs`, а не на слова; описана лестница моделей и правило кэша;
- `docs/ECONOMY_LOG.md` — журнал замеров: токены на входе и выходе, время, исход. Программного API стоимости вызова субагента нет, это подтверждено документацией, поэтому журнал ведётся вручную из `/usage`.

Чего не появляется: реестра автоматизации, контроллера, надзора, второго дизайнерского языка поверх существующего.

## 5. Метрики

Гейты этой работы. Каждый измеряется командой, а не мнением.

| Метрика | Порог | Чем измеряется |
|---|---:|---|
| гейты, закрытые скриптом | 8 из 9 | `GATES.json` содержит секцию по каждому |
| непокрытый гейт назван явно | 1 | клавиатурный проход, отдельная работа |
| прогон гейтов без участия LLM | да | скрипт запускается из командной строки |
| роли субагентов с явной моделью | 3 | frontmatter `model` в каждом файле |
| набор инструментов субагента ограничен | 3 из 3 | поле `tools` или `disallowedTools` |
| кэш субагента при серийных вызовах | 1 час | `cacheTtl` в определении |
| замеры прогона записаны | каждый | строка в `ECONOMY_LOG.md` |
| скилл не ссылается на непроверяемые гейты | 0 упоминаний | вычитка `SKILL.md` |

Приёмка работы: прогон `gates.mjs` на реальном собранном сайте, а не на примере. До появления сайта ЮНИТЕХ берётся уже собранный сайт для заказчиков.

## 6. Настройки прогона

**Исполнитель.** Работа локальная: скрипты-обёртки, три файла определений и правка markdown. По инварианту 5 это не тот объём, где рой даёт выигрыш, поэтому делаю сам.

**Развилка, которую выношу вам.** Память контура держит правило: в плагинах `E:/-7-` правки markdown разрешены напрямую, а **код плагина — только через рой**. Стандарт v2.0.0-rc.6 это правило смягчил: локальный bugfix, test, config и metrics оркестратор делает сам. Скрипты-обёртки над готовыми инструментами ближе к metrics, чем к существенной разработке, но формально это новый код в плагине. Прошу решение: делаю сам или заводим рой.

**Проверка.** Отдельной стадией и другой природой: гейты проверяет скрипт, а не я; результат работы принимает независимый контролёр, а не автор.

**Порядок.** Сначала 2.1 целиком — гейты дают пользу немедленно и сайту ЮНИТЕХ, и сайту заказчиков. Затем 2.2. Пункт 2.3 работы не требует.

**Откат.** Каждый шаг — отдельный коммит явным перечнем путей; версия плагина поднимается один раз в конце, тегом. До тега откат — обычный revert.

**Чего работа не делает.** Не публикует ничего, не трогает вендорные скиллы дизайна, не заводит второй дизайнерский язык, не меняет контракт `brief.yaml`.
