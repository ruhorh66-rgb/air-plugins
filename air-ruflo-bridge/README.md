# air-ruflo-bridge

Плагин-мост к [`ruvnet/ruflo`](https://github.com/ruvnet/ruflo) (бывш. `claude-flow`, MIT) —
кандидату на роль оркестрационного движка контура.

## Статус на 28.07.2026

**Принято решением ЛПР** — вести дальше как плагин со своим vault. Основание принятия —
контекст контура в целом (проект LAN+VPN: пять дней, крупный расход токенов, продвижения
к исходной задаче нет), **не** техническое превосходство, показанное пилотом: первый
реальный прогон (28.07, гейт хода оркестратора через ruflo) вскрыл три ограничения:

1. распределение ролей (`Architect`/`Coder`/`Tester`) было номинальным — `task_create`
   регистрировал задачи, реальную работу выполнял один процесс-воркер напрямую;
2. у ruflo нет собственного гейта человека — MCP-инструмент выполнил команду оболочки без
   единого запроса подтверждения;
3. его демон сообщает о себе неверно: `daemon stop` рапортует успех, а файл состояния
   остаётся с `running: true`.

Полный разбор и решение о составе конституции — `005_Ruflo_Wiki` (это самое знание) и
`030_AI_Pipeline_Wiki/02_WIKI/Состав конституции после ruflo — предложение (этап 3)
2026-07-28.md`.

## Что здесь есть, а чего нет

- **Есть**: этот манифест и роадмап — фиксируют рамку и то, что уже проверено.
- **Нет пока ни одного скилла.** Единственная реально построенная вещь — гейт хода
  оркестратора (`CLAIMS.md`-парсер + `air_orchestrator_gate.ps1`) — лежит в
  `air-vibecoding` (ветка `claude/orchestrator-gate-v1`), не здесь: она не специфична
  ruflo, построена как обычный код, ruflo был лишь способом её построить.
- **Проверка состояния ruflo (демон, PID) — не в этом плагине.** Отдано ВЕРЕ
  (`AIR_OS/10_AUTOMATION/vera`), которая получает под это новые роли/функционал —
  реализация ведётся отдельной сессией, см. `ROADMAP.md`.
