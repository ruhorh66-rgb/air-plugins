# Дятел Вуди

Дешёвая петля разработки под машинно проверяемую цель.

Вуди берёт множеством дешёвых ударов в одну точку, а не одним дорогим замахом. Кто
начинает с дорогой модели, машет кувалдой там, где нужен клюв.

Контракт и правила — `SKILL.md`, читать первым.

## Быстрый старт

1. В корне продукта нужен судья — скрипт, возвращающий 0 только при достижении цели.
2. Скопировать `run-config.example.json` в корень продукта как `run-config.json`
   и назвать в нём судью.
3. Написать `PLAN.md`: шаги со ступенями, по образцу `PLAN.example.md`.
4. Запустить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File F:\-7-\air-worker\skills\woody\scripts\woody.ps1 -ProductRoot <корень продукта>
```

Посмотреть разбивку, ничего не исполняя: добавить `-PlanOnly`.
Прогнать вхолостую, без вызова моделей и скриптов: добавить `-WhatIfRun`.

## Что получится

- `steps.jsonl` в корне продукта — замер каждой итерации: ступень, модель, код судьи,
  стоимость, число ходов.
- Код возврата 0 — цель достигнута; 1 — остановка по потолку, бюджету или тупику.

## Три вещи, которые стоит знать до первого запуска

**Цена определяется числом ходов, а не выбором модели.** Замер 11.08.2026: 23 137 токенов
перечитывания кэша на каждый токен выхода. Поэтому упор в потолок ходов Вуди трактует как
«сузить шаг», а не «взять модель подороже», и останавливается.

**Ступень `script` — не оптимизация, а правило.** Шаг с проверяемым точным выходом,
отданный модели, это оплаченное бесплатное.

**Судья не переписывается.** Он проверяет цель, а не исполнителя. Записанный вердикт врёт:
у AirSmeta в `.goal-verdict` лежало «8 из 10», прогон того же судьи дал «0 из 10».
