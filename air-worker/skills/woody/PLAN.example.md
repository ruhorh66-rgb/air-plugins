# План работ — образец для Вуди

Формат намеренно человеческий: правится глазами и руками, без редактора JSON.

**Форматов два, и они не равнозначны.**

```text
- [ ] <ступень>  <заголовок шага> :: <команда>          список — только работа
```

```text
| № | Шаг | Ступень | Исполнитель | Состояние |     таблица — работа И ГЕЙТЫ
|---|-----|---------|-------------|-----------|
| 1 | Собрать манифест | script | ведущая | открыт |
| 2 | Повысить права на задачу | — | ЛПР | гейт |
```

**Гейт выражается ТОЛЬКО таблицей.** В колонке ступени для него ставится прочерк или
слово «гейт»; в списке с флажками гейта нет и быть не может — там всякая строка читается
как исполняемая работа.

Найдено прогоном на живой задаче 12.09.2026: план написали по списку, и петля сказала
«шагов 7, исполняемых 7, гейтов ЛПР 0» — собираясь работать над четырьмя пунктами,
которые работой не закрываются вообще (повышение прав, разрешение на скачивание,
перезагрузка). Переписали таблицей — стало «закрыто 2, исполняемых 3, гейтов ЛПР 4»,
и каждый гейт назван.

**Правило простое: есть в работе хоть одно ожидание человека — пиши таблицей.** Список
годится только там, где всё до последнего шага закрывается работой.

- `[ ]` — шаг открыт, `[x]` — закрыт;
- ступень одна из: `script`, `haiku`, `sonnet`, `opus`;
- всё после `::` — команда; обязательна для ступени `script`, для моделей не нужна.

Разбивка на ступени и есть экономия. Вуди не начинает работу без плана намеренно:
без разбивки дорогая модель возьмётся за механическое.

## Пример

```text
- [x] script  Собрать манифест установленного :: pwsh -File tools/manifest.ps1
- [ ] script  Переписать семь скриптов на стабильные пути :: pwsh -File tools/fix-paths.ps1
- [ ] haiku   Заполнить карточки механизмов по шаблону из docs/card-template.md
- [ ] haiku   Разложить список задач планировщика в таблицу реестра
- [ ] sonnet  Починить разрешение интерпретатора по списку кандидатов
- [ ] sonnet  Добавить тест на то, что отказ реестра назван, а не проглочен
- [ ] opus    Решить, кто владеет запуском RDC при двух резидентах в трее
```

## Как выбирать ступень

Вопрос один: **чем проверяется результат шага.**

- Проверяется точным сравнением выхода — `script`. Модель здесь дефект, а не выбор.
- Проверяется глазами по известному образцу — `haiku`.
- Проверяется тестом или прогоном — `sonnet`.
- Проверяется суждением, и у задачи есть несколько защитимых решений — `opus`.

Ошибиться вниз дёшево: Вуди поднимет ступень сам, когда судья не сдвинется.
Ошибиться вверх дорого: подъём никто не отменит, и шаг будет оплачен по верхней ставке.

## Чего в плане быть не должно

- Шагов без проверяемого результата — их не закроет ни судья, ни человек.
- Шага «разобраться» — это не шаг, а отсутствие плана.
- Шага шире одной итерации: упор в потолок ходов Вуди трактует как «сузить шаг»
  и останавливается, а не поднимает модель.
