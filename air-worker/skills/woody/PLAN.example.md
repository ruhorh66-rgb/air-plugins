# План работ — образец для Вуди

<!-- ЗАГОТОВКА-НЕ-ЗАПОЛНЕНА: замени примеры ниже своими шагами и УДАЛИ ЭТУ СТРОКУ.
     Пока строка на месте, петля считает план незаполненным и работать не начинает —

Формат намеренно человеческий: правится глазами и руками, без редактора JSON.

**Форматов два, и они не равнозначны.**

```text
- [ ] <ступень>  <заголовок шага> :: <команда>          список — только работа
```

Таблица — работа И гейты. **Колонок ровно четыре:**

```text
| № | Шаг | Ступень | Судья |
|---|-----|---------|-------|
| ~~1~~ | Собрать манифест :: pwsh -File tools/manifest.ps1 | script | tools/check-manifest.ps1 |
| 2 | Переписать скрипты на стабильные пути :: pwsh -File tools/fix-paths.ps1 | script | К1: tools/check-paths.ps1 |
| 3 | Починить разрешение интерпретатора | sonnet | К2: go test ./... |
| 4 | Повысить права на задачу | — | гейт: ЛПР повышает права |
```

- закрытый шаг — зачёркнутый номер `~~N~~`;
- у ступени `script` команда пишется в колонку «Шаг» после `::` и **обязательна**;
- колонка «Судья» несёт ссылку на критерий (`К1: ...`) — открытый исполняемый шаг без неё не исполняется.

**Пятой колонки быть не должно.** Строка из пяти ячеек не разбирается ни одним выражением
разборщика, и план молча оказывается пустым. Найдено AIR-ENV-002 14.09.2026: этот самый
образец показывал таблицу из пяти колонок (`Исполнитель`, `Состояние`), пока SKILL.md и
код знали четыре, — человек, писавший строго по образцу, получал ноль шагов без единой
ошибки. Тот же день и тот же класс, что с `::`: документация разошлась с кодом, и теперь
образец разбирается тестом тем же кодом, что и настоящий план.

**Гейт выражается ТОЛЬКО таблицей.** В колонке ступени для него ставится прочерк или
слово «гейт»; в списке с флажками гейта нет и быть не может — там всякая строка читается
как исполняемая работа.

Найдено прогоном на живой задаче 12.09.2026: план написали по списку, и петля сказала
«шагов 7, исполняемых 7, гейтов ЛПР 0» — собираясь работать над четырьмя пунктами,
которые работой не закрываются вообще (повышение прав, разрешение на скачивание,
перезагрузка). Переписали таблицей — стало «закрыто 2, исполняемых 3, гейтов ЛПР 4»,
и каждый гейт назван.

**Правило простое: есть в работе хоть одно ожидание человека — пиши таблицей.** Список
годится только там, где всё до последнего шага закрывается работой.

- `[ ]` — шаг открыт, `[x]` — закрыт;
- ступень — `script` либо модель: `haiku`, `sonnet`, `opus`, с усилием или без (`sonnet:max`).
  Без усилия ступень находится в лестнице `run-config.json` по имени модели;
- всё после `::` — команда; обязательна для ступени `script`, для моделей не нужна.

Разбивка на ступени и есть экономия. Вуди не начинает работу без плана намеренно:
без разбивки дорогая модель возьмётся за механическое.

## Блок целей

Без блока целей петля план не исполняет. Решение ЛПР 14.09.2026: «без целей план —
бумажка, не видно, пришли к цели или нет».

```text
**Ц1.** инструмент переносится на стабильные пути и запускается без ручных обходов

| Критерий | Цель | Признак достижения | Чем меряется |
|---|---|---|---|
| К1 | Ц1 | манифест собран, пути переписаны | проверка `манифест и пути` |
| К2 | Ц1 | интерпретатор резолвится без правок руками | проверка `тесты` · тест `TestInterpreterResolves` |
```

«Чем меряется» — машинная грамматика без пояснительной прозы: ``проверка `имя` ``, при нужде конкретный тест — ``проверка `имя` · тест `селектор` ``, либо ``факт `f01` ``. Для проверки с `тест` её `judge.checks` объявляет шаблон `select` с `{}`.

## Пример

```text
- [x] script  Собрать манифест установленного :: pwsh -File tools/manifest.ps1
- [ ] script  Переписать семь скриптов на стабильные пути [К1] :: pwsh -File tools/fix-paths.ps1
- [ ] haiku   Заполнить карточки механизмов по шаблону из docs/card-template.md [К2]
- [ ] haiku   Разложить список задач планировщика в таблицу реестра [К1]
- [ ] sonnet  Починить разрешение интерпретатора по списку кандидатов [К2]
- [ ] sonnet  Добавить тест на то, что отказ реестра назван, а не проглочен [К1]
- [ ] opus    Решить, кто владеет запуском RDC при двух резидентах в трее [К2]
```

## Как выбирать ступень

Вопрос один: **чем проверяется результат шага.**

- Проверяется точным сравнением выхода — `script`. Модель здесь дефект, а не выбор.
- Проверяется глазами по известному образцу — `haiku`.
- Проверяется тестом или прогоном — `sonnet`.
- Проверяется суждением, и у задачи есть несколько защитимых решений — `opus`.

Ошибиться вниз дёшево: Вуди поднимет ступень сам, когда судья не сдвинется.
Ошибиться вверх дорого: подъём никто не отменит, и шаг будет оплачен по верхней ставке.

## Чего в плане быть не должно

- Шагов без проверяемого результата — их не закроет ни судья, ни человек.
- Шага «разобраться» — это не шаг, а отсутствие плана.
- Шага шире одной итерации: упор в потолок ходов Вуди трактует как «сузить шаг»
  и останавливается, а не поднимает модель.
