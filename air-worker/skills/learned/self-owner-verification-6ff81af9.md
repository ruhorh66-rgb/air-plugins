# Verify self-learning ownership and end-to-end use

## When to apply

Apply when validating a CLI’s persistent self-learning capability, especially when product-scoped learning already exists.

## Procedure

1. Record the exact installed binary version and hash.
2. Probe the self-owned learning selector separately from product-scoped learning; verify both discovery and routing diagnostics.
3. Submit any defect through the native feedback path with a stable run ID.
4. Inspect the reviewer, proposal, and ledger outputs; distinguish recorded or loaded guidance from actual use.
5. In a fresh host session, verify the current target revision, real procedure use, outcome, and observable effect.
6. Treat autonomy as unproven until cross-session use and effect are independently verified.

## Pitfalls

- Assuming product-scoped learning proves a persistent self-owner exists.
- Counting a loaded lesson, unit test, or self-report as procedural use.
- Editing the learning target manually instead of using the native feedback and review path.
- Skipping fresh-session verification of target revision, use, outcome, and effect.
