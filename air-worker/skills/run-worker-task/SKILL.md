# air-worker — исполнитель тяжёлых нероевых задач

Код контура едет через рой ruflo. Тяжёлая НЕроевая работа рою не нужна, а в сессию
оркестратора не помещается. Схема та же (`AIR_VIBECODING.md` § «Схема исполнения»):
оркестратор → отцеплённый процесс → подтверждение ЛПР кнопкой → сводка. Меняется
только то, ЧТО запускается по нажатию.

## Порядок

```text
1. python worker.py types                      какие типы задач подключены
2. python worker.py lock                       свободен ли канал бота (ОБЯЗАТЕЛЬНО до create)
3. python worker.py create <тип> <файл> --param k=v [--title ...]
4. python listener.py --once 30                ждать нажатия ЛПР и отработать
5. python worker.py status <id>                исход; python protocol.py — где ушло время
```

Скрипты — `skills/run-worker-task/scripts/`. Рантайм (база, замок, результаты,
протокол) — `E:\-4-\air-worker`, вне git.

## Чего этот канал не делает — и это не настройка

Границы взяты у `air-ruflo-bridge` и ослаблены быть не могут: они условие, при
котором Telegram-канал вообще допустим, а не параметр.

- **текст из чата командой не становится.** Читается только `callback_data` вида
  `awrun:<id>` / `awno:<id>`. Что запустится — решено В МОМЕНТ СОЗДАНИЯ заявки:
  подписанное поле `task_type` выбирает исполнителя из `executors.REGISTRY`;
- **нажатие с чужого chat_id игнорируется молча** — ответ подтвердил бы, что канал
  существует;
- **подпись проверяется в момент нажатия**, а не создания: между кнопкой и нажатием
  проходят часы. Не сошлась подпись или изменился сам материал — заявка мертва,
  а не «запустим осторожно»;
- **заявка одноразовая и с TTL.**

## Один бот на двоих — и почему это лок, а не вежливость

Бот `air-comms-telegram-bot` общий с `air-ruflo-bridge`. Long polling у Telegram
эксклюзивен по факту: апдейт достаётся тому, кто спросил первым. 10.08.2026 кнопка
air-worker досталась слушателю ruflo, и тот ответил «Заявка не найдена».

Поэтому проверяются ДВА замка, и `create` отказывается работать, пока чужой
слушатель жив:

```text
own_listener        held / free / unknown   свой замок E:\-4-\air-worker\listener.lock.json
bot_channel_foreign held / free / unknown   чужой процесс approve_listener.py
```

**`unknown` НИКОГДА не равен `free`.** Непрочитанный замок и неудавшийся опрос
процессов — это «не знаю», и в вопросе исполнения «не знаю» равносильно «занято».

## Типы задач

| Тип | Состояние | Приватность |
|---|---|---|
| `openrouter-llm` | подключён | материал уходит внешней модели — **только уровень 0** |
| `qwen-local` | разъём, не реализован | материал не покидает машину — уровень 1 |

Второй тип добавляется строкой в `executors.REGISTRY`: ядро, подпись, лок и
слушатель при этом не трогаются. Имя модели без `/` в `openrouter-llm` отвергается —
роутер отправил бы такой запрос в llama молча, а молчаливая подмена бэкенда хуже
отказа.

Внешний ход — только через локальный `E:\-4-\codex-shim\air_llm_router.py`. Своего
ключа OpenRouter плагин не держит; free-only guard роутера остаётся единственным
местом, где решается вопрос платности.

## Цикл

```text
цель   — заявка отработала, и её результат получен ИМЕННО по подтверждённому материалу
гейт   — python selftest.py (9 проверок + protocol selfcheck; провал = 1)
         + python worker.py lock (can_listen=false → не начинать вовсе)
предел — 2 круга: несошедшаяся подпись чинится не повтором, а новой заявкой
показ  — один итог: id, тип, модель, счётчики, путь результата
```

**`unknown` у замка — не «чисто».** Неудачный опрос процессов даёт третий исход, и
цикл на нём не закрывается.

## Секреты

Windows keyring, сервис `air-comms-telegram-bot`: `botfather-token`, `chat_id`,
`request-hmac-key`. Своего бота и второй записи под тот же секрет плагин не заводит
(`NEW_PLUGIN_CHECKLIST.md` § 6). Ключ подписи заводит только создающая сторона;
проверяющая — никогда, иначе удаление ключа стало бы способом обойти проверку.

## Что в логи не попадает

Содержимое обрабатываемого материала — никогда: пути, хэши, счётчики, коды. Правило
исполняется механически (`protocol._scrub` режет не-скаляры и строки длиннее 200
знаков), а не дисциплиной вызывающего кода.

## Доставка правки — три шага, не два

```text
1. поднять version в .claude-plugin/plugin.json
2. пересобрать копию в кэше маркетплейса
3. claude plugin update air-worker@air-plugins
```

Третий обязателен: бамп сам по себе плагин не переустанавливает (`ERR-2026-000203`).
Версия не поднимается, пока ЛПР не сказал «беру».
