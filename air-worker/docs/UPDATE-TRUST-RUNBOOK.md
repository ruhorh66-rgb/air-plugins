# AirWorker: подпись канала обновлений и восстановление

Статус 26.11.2026: восстановление открыто. Резервный ключ создан и проверен в хранилище, но не введён в действие. Эта инструкция не объявляет новый ключ действующим и не разрешает установку или смену ленты без проверенного перехода.

## Что подписываем

Для собственных AIR-продуктов Authenticode не обязателен. Трей AirWorker проверяет Ed25519-подпись отдельного манифеста, который связывает канал и версию с Git-ревизией, хэшами и размерами CLI/tray и хэшем полного дистрибутива. GitHub Release сам по себе не включает обновление в трее.

- Действующий ID: `air-worker-update-2026-01`; закреплённый публичный ключ: [cmd/update.go](../cmd/update.go) и [docs/update-public-key.b64](update-public-key.b64). Ключ AirKill Switch несовместим.
- Резервный ID: `air-worker-update-2026-02`; [публичный ключ](update-prerelease-v2-public-key.b64), SHA-256 32 байтов Ed25519: `08f6b7e4f44bb0398bdb1628cb518870b890abd055e2c7fb3d403085395fe790`. Ветка восстановления привязывает этот ключ только к `prerelease-v2`; legacy и stable используют прежний ключ. Закрытая часть хранится в Windows Credential Manager релизного оператора, запись `AIR/AirWorker/update-prerelease/air-worker-update-2026-02`. Секрет не передаётся publisher в аргументах, окружении или как файл. До ввода в действие нужна проверка восстановления из резервной копии.
- Закрытый ключ не помещается в код, обычный Vault/Wiki, логи, заметки, артефакты или чат. Выделенное хранилище должно ограничивать выдачу штатным релизным оператором и иметь отдельный проверенный способ восстановления. В Vault фиксируют ссылку/идентификатор секрета (не значение), ответственных и дату проверки восстановления.
- Новый ключ получает новый ID. Рабочая подпись и старый ID сохраняются, пока совместимость не доказана; новое доверие нельзя раздать через манифест, который старый клиент не может аутентифицировать.

## Выпуск и аварийный переход

1. Проверить релиз и файлы, зафиксировать исходный SHA, SHA дистрибутива, тег, SHA-256 обоих бинарников и полную контрольную сумму поставки. Выпуск и установка — разные действия.
2. При наличии действующего владельца ключа использовать [штатный publisher](../tools/publish-github-update.ps1), сначала `-VerifyOnly`, затем публикацию только в целевой канал. Для v2 режим `-Channel prerelease -SigningKeyId air-worker-update-2026-02 -VerifyOnly` обращается к Windows Credential Manager, не требует `-PrivateKey` и не публикует. Скрипт проверяет привязку релиза и пакета до подписи; изолированный клиент должен принять опубликованный манифест. Не менять stable при работе с prerelease.
3. Если действующий ключ не восстановлен, не публиковать манифест с новым ID в занятую старым клиентом ленту. Сначала выдать отдельно проверенную переходную сборку по штатному каналу установки продукта, сохранив прежний подписанный канал доступным и обеспечив откат. После перехода проверять новый ключ в новом prerelease-контуре без смены stable. Пользователь устанавливает сам. Включение нового доверия считать завершённым после теста перехода, проверки корректной подписи, отказа на неверный ключ/подменённые байты и проверки видимости релиза в трее.
4. Зафиксировать в квитанции ID и отпечаток публичного ключа, точный релиз, версию клиента, проверку канала и отдельно подтверждение установки/отката. Повторить проверку доступа и восстановления ключа на следующем выпуске.
