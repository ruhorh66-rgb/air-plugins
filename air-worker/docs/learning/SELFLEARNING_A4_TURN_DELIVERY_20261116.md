# А4 · подача процедур по задаче с лимитом объёма (16.11.2026)

Ветка `dev/airworker-a4-prompt-relevance-from-rc5` от rc.5 `7e71303`. Исходный срез
`719b0c8` (dev/airworker-hermes-relevance-20261104) перенесён cherry-pick'ом без
переписывания (`-x`), затем доработан. Узел N-110, строка А4 в
`SELFLEARNING_AB_NODE_REQUESTS_20261115.md`.

## Что было в rc.5

`UserPromptSubmit` на каждом ходе подавал те же 8 самых свежих процедур (до 16 KiB),
что и `SessionStart`, независимо от задачи. Срез `719b0c8` только переставлял подходящие
вперёд; неподходящие процедуры по-прежнему шли в каждый ход.

## Что сделано

1. **Отбор по задаче.** `selectSharedSkillsForTurn` (`learn_shared_prompt_relevance.go`)
   оставляет для хода только APPLIED-процедуры, у которых title или имя target из
   текущего индекса совпадает со словами запроса (title ×3, target ×1). Порядок:
   по счёту, при равенстве — прежний порядок по свежести. Нет совпадений — ход
   не получает процедур и не пишет `skill_loaded`. Совпадение лексическое,
   поэтому не гарантирует смысловую релевантность. Общие действия `retry`,
   `failed`, `repair` не задают тему; короткие термины `CLI` и `API` учитываются.
   Запрос только из общих слов не получает процедур. Индекс air-modules v0.1.1 уже
   отдаёт `title`; второго каталога нет, тела процедур до отбора не читаются.
2. **Лимит объёма.** Действует прежний лимит подачи `sharedLearningContextFromCatalog`:
   не больше 8 процедур и 16 384 байт текста на ход; запрос анализируется только в
   первых 4096 байтах. Отдельное число для хода не вводилось. Нужно другое — назвать.
3. **Совместимость с А3.** При одной процедуре на класс цель — `<class>.md` или
   `<class>-<16 hex>.md`; хеш-суффикс не совпадёт со словами запроса, а title берётся
   из тела процедуры. Один класс даёт не больше одной процедуры в ходе.
4. **Учёт загрузки.** Снимок контекста сессии (`context-<run>.json`) больше не
   затирается ходом:
   - ход без совпадений снимок не трогает (байт в байт);
   - ход с совпадениями добавляет свои процедуры к снимку SessionStart
     (`turnContextSnapshot`), SHA этого хода побеждает для повторной цели;
   - подписанная доставка (DeliveryMAC) ведёт себя как в rc.5: новый контекст её
     заменяет.

   Учёт `skill_loaded` в events.jsonl не менялся.

Проверки: `learn_shared_prompt_relevance_test.go` — отбор, ранжирование, кириллица,
граница запроса, сквозная подача из индекса модуля и
`TestA4TurnDeliveryKeepsSessionLoadAccounting` (SessionStart → посторонний ход →
подходящий ход).
