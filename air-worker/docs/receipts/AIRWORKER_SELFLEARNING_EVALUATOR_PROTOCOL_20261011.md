Удаление полей из нового коммита не делает опубликованные кейсы секретными. ID `AW-HOLDOUT-01…04` отныне **public regression controls**, и их результат никогда не может доказывать обобщение модели.

Новые непоказанные ранее оценочные случаи **не создаются и не публикуются до фиксации обученного результата**. Ни одна команда этой сессии не утверждает, что их удалось изолировать от обучающегося компонента.

## Штатная процедура независимого оценщика

1. После обучения зафиксировать source HEAD, runtime instance, точный `skills/learned/<target>@SHA`, ledger/review и frozen model/adapter configuration SHA; зафиксировать `FROZEN` квитанцию. Запретить auto-review/auto-apply и запись новых LEARN процедур в проверяемый экземпляр на период контрольной оценки.
2. Назначить **отдельный evaluation owner**. Сгенерировать не менее четырёх ранее не публиковавшихся свежих случаев **только после** пункта 1, используя энтропию внутри проверяющего контекста. Не использовать старые `AW-HOLDOUT-01…04`, файлы из Git history, текст из prompt или подготовленных учебных Markdown. Не записывать входы и ожидаемые ответы в GitRoot, продуктовый волт, API-подсказки learner или LEARN runtime.
3. На каждом случае предоставлять обучаемому компоненту только допустимый вход, **не ответ и не expected status**. Оценщик удерживает правильный результат и проверочный источник вне доступного для learner state (изолированный процесс/учётная запись или защищённая внешняя среда). Если такой границы нет, оценка — `NOT_PROVEN`.
4. Вызвать неизменённый native code из зафиксированного SHA, получить исход и `procedure_used` только с проверяемой реальной квитанцией. Проверяющий сравнивает ожидаемое и фактическое **после** завершения каждого испытания. Не обучать систему по ошибкам до окончания всего набора.
5. Записать после тестов машинную квитанцию `air-worker.self-learning.sealed-eval/v1`: frozen SHA, evaluator owner, среда/изоляция, генератор/seed commitment, количество случаев, success/fail, false positive, unsafe grants, external repair attribution, проверка отсутствия утечки, независимый Codex GPT-6 Sol Low PASS. Только после этого разрешено снять `NOT_PROVEN`.
6. Для предотвращения повторов минимум две независимые ошибки из новой сессии должны быть предотвращены, а не просто записаны после повторного появления.

## Безопасные технические границы

- Если evaluator и learner имеют одну Windows-учётную запись и общую файловую видимость, **запись скрытого ответа рядом с learner не считается изоляцией**. Нельзя скрыть уже закоммиченные данные флагом `hidden`, шифрованием с доступным тому же процессу ключом или переименованием файла.
- Не публиковать sealed test seeds/ответы до фиксации оценки; сохранять только commitment HASH до раскрытия итогового результата.
- Публичные негативные контроли H01…H04 полезны для регрессии, **не для проверки обобщения**.
- Никакие реальные security/permission или stop-service правила не получают auto-grant. Установка и релиз AirWorker 0.11.9 требуют отдельного «да» ЛПР.
