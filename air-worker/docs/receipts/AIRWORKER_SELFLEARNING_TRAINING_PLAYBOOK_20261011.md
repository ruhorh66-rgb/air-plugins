# AirWorker — учебная программа по собственным ошибкам сессии
11.10.2026 SGT · **CURATED TRAINING**, не автоматическое самообучение и не релиз.

## Назначение

Источник уроков: `AIRWORKER_SELFLEARNING_TRAINING_CASES_20261011.json`, 11 учебных случаев и 4 **публичных негативных контроля, не holdout**. Первоначальные ответы четырёх задач были опубликованы в GitHub и навсегда исключены из независимой оценки. Настоящие новые holdout-кейсы пока **не созданы**. Порядок независимой проверки: `AIRWORKER_SELFLEARNING_EVALUATOR_PROTOCOL_20261011.md`. Два вида фактов разделены:

- **Наблюдение:** реально виденная ошибка/квитанция, с original run/source SHA.
- **Нормативное ожидание:** будущая проверка и правильное действие. Наличие ожидания не доказывает, что установленный AirWorker его выполняет.

Через штатный `air-worker learn event` внесены *ручные кураторские* записи `AW-RETRO-T01/T02/T03/T06/T07/T08/T09/T10/T11` и отдельная коррекция ошибочной ссылки первого события `AW-RETRO-T01-FIX`. Нативные LEARN-журналы не редактировались вручную. Эти записи являются источником обучения, **не** готовыми auto-applied skills.

## Инструктивные правила, которые необходимо научить исполнять

### 1. Сначала проверка происхождения доказательства

Перед вердиктом PASS, созданием `procedure_used` или закрытием узла надо доказать точное соответствие `source_sha → run_id → immutable receipt → native result → judge verdict`. Не доверять результату, подписанному только самим заявителем, тексту модели либо совпавшей строке `status=pass`. Не списывать внешнее восстановление файлов на выученный навык.

### 2. Путь — это вся цепочка каталогов

Для файла, который влияет на классификацию ошибки, проверить **каждый компонент абсолютного пути**, в том числе Windows junction/reparse и все родительские каталоги. Смена идентичности/доступа ⇒ `NOT_PROVEN`, а не условно доверенная причина. Никакого автоматического перехода в чужое дерево.

### 3. Применение и эффект отличаются от загрузки

`proposed`, `applied`, `skill_loaded`, `procedure_used`, `outcome`, `effect` — разные машинные состояния. Нельзя создавать `procedure_used` только потому, что инструкция появилась в контексте, ключевые слова совпали или нативный валидатор выдал PASS. Если менялась конфигурация извне, отдельно записать источник восстановления.

### 4. Одно атомарное решение LEARN

Последний applied ledger, reviewer/proposal, index и SHA инструкции должны быть проверены в одной модульной транзакции с записью нативного использования. Между проверкой и записью не может проходить неподконтрольный rollback. Полезные Markdown-инструкции допустимы; executable/блокирующие правила только через доверенное решение ЛПР.

### 5. Безопасное возобновление после обрыва

Вызов Go, модели или инструмента получает стабильный `job_id`, исходный SHA, bounded deadline, PID и конечную квитанцию. После сетевого обрыва сначала искать существующий процесс/результат, а не вызывать повтор. Не считать отсутствие ответа приложения фактом остановки задачи.

### 6. Единственная нить PLAN

Нативный `plan node new` в изолированной ветке с устаревшей базой реально присвоил второй ID `N-120` другому заданию. Перед выделением нового ID проверять авторитетный PLAN/удалённый HEAD и все активные WIP; коллизия ⇒ отказ/согласование, но не ручная правка `plan/N-*`. Сохранять чужие dirty и уникальные хэндоффы. Статус из испытательной ветки не равен статусу основной.

## Как проверить обучение, а не просто документы

1. Зафиксировать исходное состояние навыков, `pending`, schema+source SHA и каталог известных процедур.
2. Передать **новую реальную** ошибку N121 в настоящий LEARN-поток автоматически, а не командой кураторского `learn event`. Reviewer должен иметь исходное событие и выдать подходящую безопасную Markdown-процедуру, либо обоснованный `no_candidate`.
3. Проверить независимым Sol Low (effort low) корректность предложенной процедуры и отсутствие опасного переписывания других навыков.
4. Новый процесс должен загрузить точный `target@SHA`, нативная операция действительно выбрать и использовать навык, результат должен иметь источник и квитанцию.
5. После фиксации обученного артефакта с source SHA независимый оценщик создаёт **четыре новых, ранее не публиковавшихся испытания** в закрытом evaluation-контуре; старые H01–H04 допустимы только как публичная регрессия. Без проверенной временной/процессной изоляции и скрытых ответов — `NOT_PROVEN`. Требуется 0 ложных положительных и 0 автоматических grant.
6. Для реальной пользы выполнить повторный дефект из другой сессии и убедиться, что навык предотвратил его, а не просто записал повторное событие. Не менее двух разных предотвращённых категорий P1 в критериях N122/N125.
