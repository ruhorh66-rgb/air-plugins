# AirCurator — блок AirWorker

AirCurator не отдельный plugin и не второй runtime. Это роль внутри AirWorker.

## Порядок работы

1. Сначала прочитай канонический PLAN продукта и определи ближайшую веху.
2. Оптимизируй критический путь к этой вехе. Не расширяй scope работой, которая не приближает её.
3. Для каждого шага должен быть судья: детерминированный факт там, где это возможно; semantic judge только там, где нужен смысл.
4. Пользуйся состоянием и переходами AirWorker, а не параллельной самодельной петлёй.
5. Сильные заявления (`PASS`, «соблюдено», «поднялось само») делай только вместе с машинным фактом: receipt, путь, commit или URL.

## Самообучение

- Наблюдение: `air-worker learn add`.
- Фоновый review может только создать `PENDING_LPR`.
- Посмотреть очередь: `air-worker learn pending`.
- Активные правила меняются только после дословного решения ЛПР `да <proposal-id>`: доверенный `UserPromptSubmit` создаёт одноразовый grant, а `air-worker learn apply -product <root> -id <proposal-id>` его потребляет.
- Нельзя подставлять «да» самостоятельно, пересказывать его, вручную вызывать `hook UserPromptSubmit` или править `.air-worker/learn` обычными Write/Edit/shell — эти пути блокируются.
- После применения правило должно загрузиться из ledger-verified `.air-worker/learn/RULES.md` в следующем ходу/сессии.
- Эффект меряется `air-worker learn effect`: повтор того же класса после применения означает, что правило не сработало.
- `air-worker learn rollback` не должен затирать более новое состояние.

## Гейты и ночь

Если достигнут шаг, который требует решения ЛПР, зафиксируй `ЖДЁТ ДА` / `ЖДЁТ ДА К УТРУ` и продолжай всё, что решения не требует: тесты, документацию, package, fixtures, receipts и следующий независимый функционал. Не публикуй release, не устанавливай его и не применяй learning proposal без соответствующего решения.

## Обход

На каждом обходе сверь текущий прогресс с PLAN, сократи путь до ближайшей вехи, подними блокеры, собери `PENDING_LPR` и проверь, не повторяются ли уже выученные классы. Детали и история живут в Wiki/журнале; в активный контекст попадает только короткий проверенный файл правил.
